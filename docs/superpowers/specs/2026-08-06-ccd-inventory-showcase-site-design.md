# CCD 库存客户展示站设计

## 背景

当前项目已经能通过朋友圈库存链路生成 `output/全量当前库.xlsx`，并在开启媒体下载时把朋友圈图片保存到 `output/media/`。用户希望在这个能力上扩展一个客户可访问的网页，用于展示当前 CCD 库存。

第一版不做在线后台。人工管理能力由 Excel 承担：用户在一张“客户展示库存 Excel”里调整展示价、隐藏商品、修改展示文案，然后双击发布脚本生成并上传静态网页。

## 目标

- 每天刷朋友圈后生成最新原始库存表和机身图。
- 自动合并更新一张人工可编辑的客户展示库存表。
- 用户在 Excel 中完成改价、隐藏、改文案等管理动作。
- 发布脚本读取客户展示库存表和出片图文件夹，生成客户展示网页。
- 客户通过固定链接在手机或电脑上查看库存、搜索、筛选和看图。

## 非目标

- 第一版不做管理后台、数据库、登录、在线下单、支付和客户留言。
- 第一版不要求网页实时修改商品；所有客户可见变更通过重新发布静态站生效。
- 第一版不在 Excel 内嵌图片，只在 Excel 中记录图片路径。

## 核心流程

```text
刷库脚本
  -> 抓取朋友圈
  -> 识别一条朋友圈对应一台 CCD
  -> 下载该朋友圈机身图
  -> 生成 output/全量当前库.xlsx
  -> 合并更新 manual/客户展示库存.xlsx

人工整理
  -> 打开 manual/客户展示库存.xlsx
  -> 修改展示价、是否展示、展示文案、出片图型号等字段

发布脚本
  -> 读取 manual/客户展示库存.xlsx
  -> 读取 sample_assets/ 型号出片图文件夹
  -> 复制机身图和出片图到站点产物
  -> 生成 products.json
  -> 构建静态网页
  -> 上传到线上
```

## 数据边界

### 原始库存表

路径：`output/全量当前库.xlsx`

用途：自动生成的原始数据，不建议人工修改。它记录朋友圈识别出的库存事实，包括型号、成本价、发布时间、来源、原文文案和机身图路径。

### 客户展示库存表

路径：`manual/客户展示库存.xlsx`

用途：网页发布的唯一业务数据源，允许人工编辑。它由原始库存表合并生成，但保留人工覆盖字段。

建议字段：

| 字段 | 来源 | 用途 |
| --- | --- | --- |
| 商品ID | 自动生成 | 稳定识别一台商品，避免重复和覆盖错误 |
| 型号 | 原始库存 | 给客户展示 |
| 品牌 | 自动推导，可人工修正 | 筛选使用 |
| 成本价 | 原始库存 | 内部参考，不一定展示 |
| 展示价 | 自动初始化，可人工修改 | 客户看到的价格 |
| 是否展示 | 自动初始化为是，可人工修改 | 代替删除商品 |
| 发布时间 | 原始库存 | 排序和辅助判断 |
| 来源 | 原始库存 | 内部参考，可选择是否展示 |
| 原文文案 | 原始库存 | 保留朋友圈原文 |
| 展示文案 | 自动初始化，可人工修改 | 客户看到的文案 |
| 机身图路径 | 原始库存 | 绑定单台商品的朋友圈图片 |
| 出片图型号 | 自动标准化，可人工修改 | 匹配出片图文件夹 |
| 备注 | 人工 | 内部记录 |

### 机身图

路径示例：

```text
output/media/<商品ID>/
  image-1.jpg
  image-2.jpg
```

机身图是商品级图片，来自朋友圈。因为业务约束是“一条朋友圈对应一台 CCD”，所以同一条库存记录下的朋友圈图片都归属于这台商品。

### 出片图

路径示例：

```text
sample_assets/
  三星a40/
    sample-1.jpg
    sample-2.jpg
    sample-3.jpg
    sample-4.jpg
```

出片图是型号级图片，由用户人工整理。多个同型号商品可以共用同一个出片图文件夹。

## 合并规则

合并脚本从 `output/全量当前库.xlsx` 读取最新库存，再更新 `manual/客户展示库存.xlsx`：

- 新商品：追加到客户展示库存表，`展示价` 默认等于成本价或按加价规则生成，`是否展示` 默认是。
- 已存在商品：更新原始字段，如成本价、发布时间、原文文案、机身图路径；保留人工字段，如展示价、是否展示、展示文案、出片图型号、备注。
- 原始表消失的商品：不直接删除，可标记为“原始库存缺失”或保留现状，由用户决定是否隐藏。
- 人工隐藏商品：即使第二天仍在原始库存里，发布网页时也不展示。

商品ID应优先使用稳定来源字段组合生成，例如朋友圈记录 key、来源 wxid、发布时间、型号。不要只用型号，因为同型号可能有多台库存。

## 型号标准化

网页匹配出片图时使用标准化 key，不直接依赖显示型号。

规则：

- 去掉空格、横线和大小写差异。
- 中文品牌和英文品牌归一到同一个品牌名。
- 保留原始显示型号给客户看。
- 允许用户在 `出片图型号` 字段手动修正匹配结果。

示例：

| 显示型号 | 出片图型号 |
| --- | --- |
| 三星 A40 | 三星a40 |
| samsung a40 | 三星a40 |
| 佳能 IXUS 95 | 佳能ixus95 |

## 网页功能

客户展示版第一屏直接进入库存列表。

必须支持：

- 商品卡片展示：型号、展示价、展示文案、机身图、出片图。
- 搜索：型号、品牌、展示文案、原文文案。
- 品牌筛选：佳能、索尼、富士、尼康、三星、柯达、奥林巴斯、卡西欧、松下等。
- 价格筛选：100 以下、100-199、200-299、300-499、500-799、800 以上。
- 图片筛选：有机身图、有出片图。
- 排序：最新发布、价格低到高、价格高到低。
- 手机端适配：客户在微信、手机浏览器和电脑浏览器里都能看。

建议暂缓：

- 商品详情页。
- 在线询价按钮。
- 密码访问。
- 管理后台。
- 客户收藏和下单。

## 发布策略

第一版采用静态站发布。

建议脚本：

```text
run_full_mode.bat
```

负责刷朋友圈、下载机身图、生成原始库存表、合并更新客户展示库存表。

```text
publish_site.bat
```

负责读取客户展示库存表、匹配出片图、生成静态站产物并上传。

分成两个脚本是为了保留中间的人工 Excel 管理环节。每天实际操作为：

```text
双击 run_full_mode.bat
打开 manual/客户展示库存.xlsx 修改
双击 publish_site.bat
```

## 错误处理

- 机身图缺失：商品仍可发布，网页显示暂无机身图。
- 出片图缺失：商品仍可发布，网页显示暂无出片参考。
- Excel 字段缺失：发布脚本停止，并提示缺失字段名。
- 图片路径失效：发布脚本记录失败商品和路径，网页不引用不存在的图片。
- 型号匹配不到出片图：不阻断发布，生成缺图报告，方便用户后续补图。
- 客户展示库存表不存在：首次运行时由原始库存表自动创建。

## 验证

实现完成后需要覆盖以下验证：

- 原始库存表能合并生成客户展示库存表。
- 人工修改的展示价、是否展示、展示文案在下一次合并后不丢失。
- 发布脚本只发布 `是否展示=是` 的商品。
- 同型号多台商品能各自保留不同机身图，并共用同一组出片图。
- 缺机身图、缺出片图、缺字段时有明确结果或错误提示。
- 网页在手机和桌面视口下无文字重叠，搜索、筛选、排序可用。

## 第一版交付结果

- 一张稳定的 `manual/客户展示库存.xlsx`。
- 一个 `sample_assets/` 出片图目录规范。
- 一个静态客户展示网页。
- 一个刷库合并脚本。
- 一个发布脚本。
- 一份缺图/异常报告，帮助后续补图。
