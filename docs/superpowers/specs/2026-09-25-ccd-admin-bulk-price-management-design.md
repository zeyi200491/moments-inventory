# CCD 管理后台批量改价与管理体验优化设计

## 1. 目标

本次改造面向星星 CCD 展示系统管理者，优先解决批量改价缺少明确价格范围、操作范围不清晰、预览信息不足和全库误操作风险，同时逐步提升整个管理后台的日常维护效率。

核心目标：

1. 管理者可以按明确价格段筛选商品并批量加价、减价或设置固定价格。
2. 管理者在执行前能清楚看到作用范围、匹配数量、实际修改数量和详细价格变化。
3. 全库操作、已售商品和隐藏商品不会被含糊地纳入批量处理。
4. 保留现有快照、版本检查、事务、幂等提交和撤销能力。
5. 将批量操作和商品筛选放到同一个管理上下文中，降低理解和滚动成本。

## 2. 当前问题

### 2.1 批量改价依赖远处的筛选区

当前批量操作中心没有独立的价格区间控件。未勾选商品时，前端把下方“商品管理”的筛选条件复制到批量请求中。这种能力对管理者不可见，容易出现“以为只改一部分，实际改了更多商品”的情况。

### 2.2 现有阶梯规则与业务价格段不一致

当前“按原价阶梯加价”在后端写死为：

- 300 元以下增加 100 元。
- 300～499 元增加 170 元。
- 500～799 元增加 210 元。
- 800 元以上增加 300 元。

本次需要的管理价格段为：

- 200 元以内。
- 201～300 元。
- 301～600 元。
- 601～800 元。
- 801 元以上。

继续维护写死规则会让运营规则难以理解，也不方便以后调整金额。

### 2.3 预览数量语义不准确

当前页面把匹配商品总数显示成“即将影响”的数量，但固定价格与原价格相同的商品不会真正写入。管理者看到的预览数量可能与最终修改数量不同。

### 2.4 操作记录信息不足

当前批量操作日志没有完整保存筛选摘要、价格范围和金额规则。改价可以撤销，但批量隐藏和批量显示的前端没有提供撤销入口。

### 2.5 后台信息结构过长

当前访问设置、买前流程、图片橱窗、合作方、首页专栏、诊断工具、出片图匹配、批量操作、新增商品和商品管理都放在一张长页面中。管理者日常维护商品时需要大量滚动。

## 3. 业务定义

### 3.1 价格筛选基准

第一阶段统一使用“执行前的当前展示价”作为筛选基准。

原因：当前展示价是客户实际看到的价格，可能已经包含人工覆盖。按当前展示价筛选，管理者能直接预测改价结果。

系统保留“导入原价”作为预览参考信息，但第一阶段不使用导入原价决定商品属于哪个价格段。后续若确有业务需要，再增加“筛选基准：当前展示价/导入原价”的高级选项。

### 3.2 价格段边界

商品价格为整数，所有上下限均为包含关系。使用不重叠区间：

| 页面名称 | 最低价 | 最高价 |
| --- | ---: | ---: |
| 200 元以内 | 无 | 200 |
| 201～300 元 | 201 | 300 |
| 301～600 元 | 301 | 600 |
| 601～800 元 | 601 | 800 |
| 801 元以上 | 801 | 无 |

另外提供“全部价格”和“自定义价格区间”。自定义区间要求最低价小于或等于最高价。

### 3.3 商品作用范围

批量操作必须明确选择以下范围之一：

1. 已勾选商品：只处理商品列表中已勾选的商品。
2. 当前筛选结果：处理所有符合当前商品筛选和批量价格范围的商品，范围可以跨分页。
3. 全部库存：必须由管理者主动选择，不能作为默认值。

界面不再通过“有没有勾选商品”暗中改变操作范围。若管理者在存在勾选商品时切换到“当前筛选结果”，页面必须明确显示本次不会只处理勾选商品。

作用范围先确定基础商品集合，随后统一应用批量工作台中的价格区间和商品状态条件。因此，“已勾选商品”仍会排除不符合所选价格区间的商品；“全部库存”也不会绕过价格区间和状态条件。

### 3.4 商品状态默认值

批量改价默认只包含：

- 未售商品。
- 当前展示中的商品。

管理者可以主动选择“包含隐藏商品”。已售商品默认排除；若业务需要处理已售商品，必须显式开启并在预览中单独统计。

以上默认值只适用于批量改价。批量隐藏和批量显示继续使用与操作目标相符的状态条件，例如“批量显示”必须能够选择当前隐藏商品。

### 3.5 改价方式

第一阶段支持：

- 统一加价：新价格 = 当前展示价 + 金额。
- 统一减价：新价格 = 当前展示价 - 金额，新价格不得小于 0。
- 固定价格：所有目标商品改成指定展示价。

金额必须是非负整数。统一加价和统一减价的金额必须大于 0。固定价格允许为 0，但必须在确认窗口中显示高风险提醒。

现有写死的“按原价阶梯加价”不再作为默认运营入口。第二阶段用可配置的多价格段规则代替。

## 4. 批量操作界面设计

### 4.1 位置

将批量操作工作台放入“商品管理”模块，位于商品筛选区与商品列表之间。这样筛选条件、命中数量、勾选状态和批量操作处于同一上下文。

### 4.2 工作台结构

工作台依次包含：

1. 作用范围：已勾选商品、当前筛选结果、全部库存。
2. 价格范围：快捷价格段和自定义范围。
3. 商品状态：展示中、隐藏、未售、已售。
4. 改价方式：加价、减价、固定价格。
5. 金额输入。
6. 生成预览按钮。
7. 当前作用范围摘要。

金额输入标签随改价方式变化：

- 加价时显示“每台增加金额”。
- 减价时显示“每台减少金额”。
- 固定价格时显示“新的展示价格”。

### 4.3 选择状态栏

商品列表顶部增加固定状态栏，显示：

- 当前结果共多少台。
- 当前页显示多少台。
- 已选择多少台。
- 选择当前页。
- 选择全部筛选结果。
- 清空选择。
- 对已选商品执行批量操作。

“选择当前页”和“选择全部筛选结果”必须使用不同文案，避免跨分页选择误解。

### 4.4 预览

预览顶部显示：

- 匹配商品数。
- 实际修改数。
- 价格不变数。
- 跳过商品数及原因。
- 已售商品数。
- 隐藏商品数。
- 最低新价格和最高新价格。
- 全部商品价格变化合计。
- 当前筛选摘要。
- 预览到期时间和剩余时间。

预览明细至少显示：

- 型号和品牌。
- 导入原价。
- 当前展示价。
- 新展示价。
- 单台变化金额。
- 展示和已售状态。
- 跳过原因。

页面最多渲染前 200 条明细，并明确提示“只展示前 200 条”。完整结果可以导出 CSV，CSV 只包含当前预览快照，不重新查询实时数据。

### 4.5 预览失效

以下任一条件变化后，旧预览立即失效，确认按钮禁用：

- 作用范围。
- 商品筛选条件。
- 价格区间。
- 商品状态条件。
- 改价方式。
- 金额。
- 商品勾选集合。

管理者必须重新生成预览。

### 4.6 最终确认

最终确认窗口显示完整句子，例如：

> 将对“当前筛选结果”中当前展示价为 201～300 元的 79 台未售商品统一加价 50 元；另有 7 台价格不变或被跳过。

以下情况增加醒目提醒：

- 选择全部库存。
- 实际修改数量超过 200 台。
- 包含已售商品。
- 固定价格为 0。

## 5. 后端设计

### 5.1 第一阶段复用现有筛选能力

现有批量筛选请求已经支持 `priceMin`、`priceMax`、`visible`、`sold` 等字段。第一阶段由前端将批量工作台的明确选项转换为这些字段，不需要修改数据库结构。

后端继续作为最终校验方，不能只依赖前端：

- 校验价格范围。
- 校验金额。
- 校验作用范围。
- 防止全部库存被隐式选择。
- 校验减价后价格不小于 0。

### 5.2 预览响应

预览响应增加：

- `matchedCount`：符合筛选条件的商品数。
- `changedCount`：实际会发生变化的商品数。
- `unchangedCount`：新旧值相同的商品数。
- `skippedCount`：因状态或业务规则跳过的商品数。
- `summary`：结构化的筛选和规则摘要。
- `priceStats`：最低、最高和合计变化。
- `skipReasons`：按原因分组的数量。

执行接口只写入真正发生变化的商品。

### 5.3 快照与并发保护

保留现有机制：

- 预览快照保存完整目标集合。
- 预览有效期为 15 分钟。
- 执行时检查每台商品的 `row_version`。
- 任一商品发生冲突时，整个操作拒绝并回滚。
- 使用幂等键防止重复提交。
- 所有商品和操作日志在同一个事务中提交。

### 5.4 操作日志

操作日志保存：

- 操作范围。
- 商品筛选条件。
- 价格筛选基准。
- 价格区间。
- 改价方式和金额。
- 匹配数量、修改数量和跳过数量。
- 创建时间、执行结果和撤销状态。

操作记录列表直接展示人能读懂的摘要，并允许查看具体明细。

批量改价、批量隐藏和批量显示都支持版本保护下的撤销。若商品在操作后又被修改，撤销必须拒绝，并提示重新检查商品。

## 6. 第二阶段：多价格段一次改价

当单价格段工作台稳定后，增加规则表：

| 启用 | 当前展示价 | 改价方式 | 金额 |
| --- | --- | --- | ---: |
| 是 | ≤200 | 加价 | 管理者填写 |
| 是 | 201～300 | 加价 | 管理者填写 |
| 是 | 301～600 | 加价 | 管理者填写 |
| 否 | 601～800 | 加价 | 管理者填写 |
| 否 | ≥801 | 加价 | 管理者填写 |

规则必须满足：

- 区间不重叠。
- 每台商品最多命中一条规则。
- 未命中规则的商品不修改，并计入跳过统计。
- 预览按价格段分组显示匹配和修改数量。
- 一次执行产生一条父操作记录，撤销时整体撤销。

第二阶段需要扩展请求模型，使用结构化 `priceRules` 列表，不再使用后端写死阶梯金额。

## 7. 管理后台整体优化

### 7.1 信息结构

将后台划分为五个导航模块：

1. 数据概览。
2. 商品管理。
3. 页面内容。
4. 图片与出片图。
5. 系统工具。

第一轮可以使用同页锚点和固定导航，减少改造风险；后续根据模块复杂度再决定是否拆分独立路由。

### 7.2 数据概览

登录后显示：

- 商品总数。
- 展示中、已隐藏和已售数量。
- 缺机身图和缺出片图数量。
- 来源中缺失数量。
- 手动改价数量。
- 价格为 0 的数量。
- 最近导入时间。
- 最近批量操作。

统计卡片可以点击并跳转到对应的商品筛选结果。

### 7.3 快捷视图与筛选状态

提供系统快捷视图：

- 正在出售。
- 已售但仍展示。
- 没有机身图。
- 没有出片图。
- 手动改过价格。
- 来源中缺失。
- 价格为 0。
- 最近导入商品。

商品筛选条件同步到网址查询参数，刷新后保留，也可以通过复制网址复现同一个管理视图。

后续允许管理者给自定义筛选命名并保存在本机或后台配置中。

### 7.4 删除与恢复

商品、图片、相册、专栏、购买步骤和合作方的删除操作必须确认。确认内容显示对象名称和影响范围。

适合恢复的业务内容优先采用软删除或短时间撤销。物理文件删除和数据库记录删除应分开处理，避免因误删数据库记录导致图片不可恢复。

### 7.5 状态反馈和无障碍

- 异步保存、预览、执行和错误信息使用统一状态组件。
- 动态状态区域使用 `aria-live="polite"`。
- 操作开始后按钮显示进行中状态并避免重复提交。
- 所有表单控件有清晰标签。
- 所有交互元素有明显的 `:focus-visible` 样式。
- 筛选、预览和确认可以使用键盘完成。
- 手机布局保证按钮不溢出，重要确认按钮不被固定区域遮挡。

## 9. 验收标准

### 9.1 价格边界

- 200 元进入“200 元以内”。
- 201 元进入“201～300 元”。
- 300 元进入“201～300 元”。
- 301 元进入“301～600 元”。
- 600 元进入“301～600 元”。
- 601 元进入“601～800 元”。
- 800 元进入“601～800 元”。
- 801 元进入“801 元以上”。

### 9.2 作用范围

- 已勾选商品模式不会修改其他商品。
- 当前筛选结果模式可以处理跨分页结果。
- 全部库存不能被隐式选中。
- 价格范围与其他商品筛选条件同时生效。

### 9.3 预览与执行

- 页面分别显示匹配、修改、不变和跳过数量。
- 修改任一条件后旧预览立即失效。
- 固定价格与当前价格相同的商品计入不变数量。
- 已售商品默认跳过。
- 预览后商品被修改时，整个执行拒绝且不产生部分写入。
- 重试同一提交不会重复加价。

### 9.4 撤销

- 撤销后恢复原展示价。
- 撤销后恢复原价格覆盖状态，而不仅是价格数字。
- 商品在批量操作后又被修改时，撤销被安全拒绝。

### 9.5 管理体验

- 管理者不需要滚动到另一个模块才能理解批量范围。
- 当前页、全部筛选结果和全部库存的范围始终清楚。
- 电脑和手机布局均可完成操作。
- 键盘可以完成价格筛选、预览和确认。

## 10. 实施顺序

1. 将批量改价工作台并入商品管理，增加明确作用范围和价格段。
2. 完善后端校验与预览统计。
3. 完善操作日志、确认和撤销。
4. 增加商品选择状态栏和快捷筛选。
5. 增加后台导航与数据概览。
6. 在第一阶段稳定后增加多价格段一次改价。

这个顺序优先交付直接影响日常改价的能力，并在不改变现有数据库结构的情况下保留当前可靠的事务和回滚机制。
