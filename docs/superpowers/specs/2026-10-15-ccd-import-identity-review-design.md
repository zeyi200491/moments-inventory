# CCD 导入身份复核队列设计

## 目标

让管理员在本地 CCD 管理后台处理重发商品身份不确定的导入行，避免按型号自动合并，也避免未经确认地新增重复商品。商品和媒体仍以本地 SQLite/本机目录为唯一可写数据源；Cloudflare 只接收本地快照。

## 当前流程与边界

现有导入入口是 CLI：读取 Excel、按稳定来源键精确关联、生成预览并提交。完全相同的来源键可以安全复用商品；来源键重复、跨来源冲突和多个行指向同一商品会拒绝。管理后台没有导入候选队列，因此无法在一个可见流程中逐条选定重发商品对应关系。

本设计只补本地后台导入流程，不修改 Cloudflare/D1 写入能力，不触碰正式库，不改“来源缺失标记并人工复核”的已确认策略。样片低置信匹配也继续保持不自动重绑。

## 管理员流程

1. 管理员在后台上传工作簿，系统完整解析并保存为待复核批次，不改变库存。
2. 来源键与当前商品/身份别名完全一致的行可自动关联；只有型号和品牌相似的记录仅作为候选，不自动关联。
3. 每个未确定行展示来源 ID、稳定键、型号、品牌、价格、图片概况及候选商品。管理员逐条选择“关联现有商品”“新建商品”或“跳过”。来源键冲突或一个目标被多个导入行认领时，必须人工消解。
4. 页面展示插入、更新、跳过、全量缺失标记数量及差异摘要。全部导入行都有处理决定后，管理员确认提交。
5. 提交前重新检查来源批次、来源键唯一性、目标商品行版本和全量范围；任一冲突使整个事务拒绝并保留待复核批次。
6. 提交后更新商品、图片关系、来源别名、导入日志和库存修订号；一个 SQLite 事务整体成功或回滚。全量导入中消失的商品按现策略标记 `missing`，不自动下架。

## 身份规则

- 精确稳定来源键或已确认别名是唯一自动关联条件。
- 型号、品牌、价格、发布时间或图片相似度只能生成候选提示，不能自动改变商品归属。
- 管理员确认“关联现有商品”后，将该来源键登记为该商品的来源身份别名；原 `product_id` 与 `public_id` 保持不变，人工覆盖、已售状态、栏目与媒体关联随商品保留。
- 若来源键已归属另一个商品，除非管理员先在复核批次中明确解决冲突，否则不能重绑。
- 无稳定来源键的行可以由管理员选择新建或关联；系统不声称未来能自动识别其再次重发。
- “跳过”行不写库存，也不参与本次已处理行的导入计数；全量来源范围仍以工作簿完整性声明和现有缺失规则校验。

## 数据与接口边界

- 使用本地 SQLite 保存批次、逐行解析结果、管理员决定、目标商品版本快照及身份别名；只存解析所需字段和内容摘要，不保存额外的 Excel 原始副本。
- 批次状态只允许 `pending`、`committed`、`discarded`；提交/放弃均有明确操作。已提交批次不可再次编辑。
- 所有新接口必须依赖现有管理员会话；普通客户接口不得返回候选、来源键、原始文案或复核数据。
- 身份别名以 `(source_scope, source_key)` 唯一；一次提交内同时检查现行 `source_product_key` 与历史别名，避免两套映射分叉。
- 管理员身份仍是当前单一共享管理员；日志记录批次、来源摘要、行级决定、目标商品和时间，不记录口令。

## 失败处理

- Excel 格式、字段、行号错误：上传不产生可提交批次，并显示可定位的错误。
- 不能判断的行：保持待复核；不得暗中用型号/图片强制归并。
- 商品在预览后被其他进程更新：提交返回版本冲突，刷新候选与差异后重新确认。
- 数据库中途失败：商品、图片、别名、日志和修订号全部回滚，批次仍可重试。
- 请求响应丢失：客户端保留批次 ID 和提交幂等键，可查询状态或使用同键安全重试。
- 管理员放弃：标记/清理暂存行；不变更商品或身份关系。

## 验收范围

- 同键精确关联；相同型号不同实物不自动合并；低置信行等待逐条人工选择。
- 关联旧商品后重发保留公开身份、价格/文案/显隐覆盖、已售状态、图片和栏目关系；新键作为别名后可再次精确关联。
- 同批重复键、别名冲突、目标重复认领、跨来源键和陈旧版本均阻止提交且不产生部分写入。
- 新建、关联、跳过三种决定及 A→B→A 来源更新均有 API/事务测试。
- 后台上传、逐条决定、刷新页面恢复、确认提交、失败重试均有真实浏览器验收；客户接口数据中没有身份复核字段。
- 所有自动化验证使用临时 SQLite 与虚构文件；不访问正式数据库或 Cloudflare。

## 替代方案与取舍

商品行来源键编辑成本最低，但管理员必须先离开导入流程搜索商品、手工改键并重跑工作簿；没有来源行与目标候选的审阅记录，也很难解释全量缺失统计。完整复核队列需要增加暂存表、别名表、接口和页面，但直接覆盖业务方选定的“后台逐条确认”，并在提交前集中检查版本与身份冲突，因此采用完整队列。

## 暂不包含

- Cloudflare/D1 作为第二套可写库存。
- 基于型号、图片、价格或文案的自动合并/自动重绑。
- 自动下架来源缺失商品。
- 多管理员角色、审批流或云端账号体系。
- 正式数据身份迁移、数据库重写或正式发布操作。
