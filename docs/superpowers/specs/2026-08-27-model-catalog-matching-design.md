# 朋友圈型号库匹配设计

## 背景

当前朋友圈商品提取链路中，型号识别主要依赖 `config/models.txt` 的线性关键词匹配，并辅以 `parser.py` 中的品牌加型号正则。实际词库只有约 453 条，面对大量 CCD、CMOS、MOS 数码相机型号时覆盖不足，导致朋友圈文案里明明有商品型号却无法进入后续价格、合并和导出链路。

用户提供的 `C:/Users/19577/Desktop/ccd型号/相机型号搜索匹配数据库_完整合并版.xlsx` 可以作为新的型号主数据源。该文件的 `完整型号主表` 约有 3368 个规范型号，包含品牌、英文品牌名、规范型号、安全搜索匹配名称合集、全部搜索匹配名称合集、有歧义名称和安全标准化匹配键；`使用说明` 明确建议程序优先使用安全搜索匹配名称合集，并把全部搜索匹配名称合集与品牌结合使用。

## 目标

把型号识别从“小词库线性匹配”升级为“Excel 型号库离线索引 + 运行时高效多模式匹配 + 上下文角色判断”。目标是明显提高召回率，同时避免把平替、对比、否定、适配语境里的型号错误当作主商品型号。

## 非目标

- 不改变 WeFlow 朋友圈抓取、warmup、分页、入库和导出主流程。
- 不把 Excel 文件作为每次运行都读取的在线依赖。
- 不引入后台管理界面。
- 不在第一阶段实现图片识别型号。
- 不把低置信候选直接当成正式库存型号。

## 数据源策略

新增一个型号库构建步骤，从 Excel 的 `完整型号主表` 读取这些字段：

- `品牌`
- `品牌英文名`
- `规范型号/物理机型`
- `安全搜索匹配名称合集`
- `全部搜索匹配名称合集`
- `有歧义名称`
- `安全标准化匹配键`

构建结果写入 `data/model_catalog_index.json`。正常执行 `sync`、`batch-run` 和 `orchestrated-run` 时只读取 JSON 缓存，不直接打开 Excel。

`config/models.txt` 保留为人工补丁词库，用于临时覆盖 Excel 未收录但业务中已经确认的写法。补丁词库优先级高于正则兜底，但不应绕过平替、否定、歧义判断。

## 匹配架构

新增三个小模块：

- `src/moments_inventory/model_catalog.py`：负责从 Excel 构建型号索引 JSON，校验必需列，去重并标记安全名、全部名和歧义名。
- `src/moments_inventory/model_matcher.py`：负责加载 JSON，构建运行时多模式匹配器，并返回所有命中候选及位置。
- `src/moments_inventory/model_context.py`：负责根据价格、行位置、品牌、平替词、否定词和适配词，对候选型号做角色判断与排序。

`parser.py` 继续负责最终 `ParsedFields` 输出，但 `_pick_model()` 的主路径改为调用新的型号匹配器；原有品牌加型号正则保留为兜底。

## 性能策略

不能对每条朋友圈逐个扫描 1 万多个型号别名。运行时应在进程内构建一次多模式匹配索引，每条文案只扫描一遍。

优先方案是纯 Python Aho-Corasick 自动机，避免 Windows 部署新增二进制依赖。若后续性能不足，再评估 `pyahocorasick` 或 `ahocorasick-rs`。

匹配流程：

1. 启动或首次解析时加载 `data/model_catalog_index.json`。
2. 构建 alias 到规范型号的多模式索引。
3. 对单条朋友圈正文做一次扫描，产出所有命中候选。
4. 对重叠命中做长词优先过滤。
5. 用上下文规则选择主商品型号。

## 型号角色规则

命中的型号候选分为：

- `primary`：主商品型号，可以作为库存记录型号。
- `reference`：参考、平替、对比型号，不能作为主商品型号。
- `negative`：否定语境型号，不能作为主商品型号。
- `ambiguous`：歧义或证据不足候选，不能直接进入正式主型号。

平替和对比词包括：

- `平替`
- `替代`
- `对标`
- `类似`
- `媲美`
- `参考`
- `同款感觉`
- `拍人像也是`
- `像`

否定词包括：

- `不是`
- `非`
- `不要`
- `不等于`
- `不是那款`

适配和配件语境词包括：

- `适用`
- `兼容`
- `电池适配`
- `充电器适配`
- `配件`

候选型号前方近距离出现平替、对比、否定、适配词时，该候选降级为 `reference`、`negative` 或低置信候选。示例文案：

```text
980💰佳能ixus100 香槟色
成色不错屏幕贴膜功能完好 1210万像素 3倍光学变焦。平替佳能ixus130 拍人像也是绝绝子！
配件：充电器 电池 电脑读卡器 内存卡 贴纸
```

正确识别结果：

- 主商品型号：`佳能ixus100`
- 参考型号：`佳能ixus130`
- 正式导出型号：只使用 `佳能ixus100`

## 主型号选择规则

多个候选同时命中时，按以下顺序打分：

1. 与价格符号或价格数字同一行且距离最近。
2. 出现在第一行或商品开头。
3. 命中带品牌完整别名。
4. 命中安全搜索匹配名称。
5. 同文案附近存在品牌词。
6. alias 更长、信息量更高。
7. 不在平替、对比、否定、适配语境中。
8. 不属于跨品牌或同品牌歧义名。

如果最高候选仍是歧义或低置信，不直接写入主型号，而是标记 `needs_manual=True`，并保留候选信息供排查。

## 解析结果扩展

在不破坏现有导出主字段的前提下，扩展内部解析结果：

- `model`
- `price`
- `serial_no`
- `model_confidence`
- `matched_alias`
- `model_candidates`
- `ignored_reference_models`
- `needs_manual`

第一阶段可以只在内部 dataclass 中保留这些字段；正式 Excel 是否新增“匹配置信度/匹配说明”列可单独开关，避免影响现有交付表结构。

## 错误处理

- Excel 缺少必需列时，索引构建命令直接失败并说明缺列名。
- JSON 缓存不存在时，默认回退到现有 `config/models.txt` 与正则逻辑，同时记录警告。
- JSON 缓存损坏时，回退旧逻辑并提示重建索引。
- 命中多个高置信但互相冲突的型号时，不自动选择，标记人工复核。

## 测试要求

必须新增这些测试：

- Excel 主表能生成去重后的索引。
- 安全别名能匹配到规范型号。
- 带品牌短型号优先于跨品牌歧义短型号。
- `980💰佳能ixus100 ... 平替佳能ixus130` 选择 `佳能ixus100`。
- `平替佳能ixus130，佳能ixus100 980💰` 选择 `佳能ixus100`。
- `佳能ixus100 980💰，不是佳能ixus130` 选择 `佳能ixus100`。
- `佳能ixus100/ixus130 对比` 不自动选择主型号。
- `a100 300💰` 在无品牌时标记歧义或待复核。
- 现有 `parser.py` 的价格、编号和旧词库测试继续通过。
- 性能测试确认大别名库下单条文案匹配不走 O(文案数 × 别名数) 的线性扫描。

## 验收标准

- 新型号库覆盖 Excel 中的规范型号和安全匹配名。
- 平替、对比、否定、适配语境中的型号不会被错误选为主商品型号。
- 当前朋友圈同步、批处理、编排导出命令保持兼容。
- 无型号索引缓存时旧逻辑仍可运行。
- 新增测试和既有 `tests/test_parser.py`、`tests/test_matcher.py`、`tests/test_exporter.py` 通过。
