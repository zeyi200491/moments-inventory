# 客户展示页性能与销售转化优化设计

日期：2026-08-14

## 背景

当前客户展示页已经具备口令访问、库存展示、品牌/价格/搜索筛选、商品详情、机身图/出片图区分、图片放大、首页专栏和后台管理能力。当前库存量约 16026 台，前端虽然只渲染首批 80 条，但 `/api/public/products` 仍会一次性返回全量商品数据。这个设计在电脑上还能接受，在客户手机上会明显增加首屏等待、流量消耗和浏览器内存压力。

这次优化目标是把客户展示页从“能看库存”升级为“手机打开快、找货快、方便回微信咨询、主推商品更显眼”。

## 目标

1. 客户页商品列表改为服务端分页，接口每次只返回当前需要展示的一批商品。
2. 搜索、品牌、价格、标签筛选全部在服务端执行，避免把 16026 台商品一次性发给浏览器。
3. 增加更细的销售标签筛选：新手推荐、礼盒装、长焦、自拍、小巧、冷白皮、氛围感、500以内、800以内、千元热门、300-500 推荐。
4. 商品卡片和详情页增加“复制咨询文案”按钮，让客户可以复制该型号完整文案后回微信发给星星CCD。
5. 客户从列表进入详情页再返回时，恢复原来的筛选条件、已加载数量和滚动位置。
6. 首页顶部专栏升级为更强的销售橱窗：今日主推、预算 300-500 推荐、新手闭眼入、礼盒装专区、最近上新。

## 非目标

1. 本阶段不做客户收藏功能。
2. 本阶段不做浏览统计、转化率统计或客户行为分析。
3. 本阶段不做复杂推荐算法，只做规则筛选和手动专栏主推。
4. 本阶段不改后台登录、口令机制、发布方式和数据库类型。

## 总体方案

采用“服务端查询 + 前端逐页加载 + 状态恢复 + 销售动作增强”的方案。

前端不再维护全量商品数组，而是维护当前查询条件、当前 offset、已加载商品列表和 total。每次搜索、筛选或点击显示更多，前端把条件传给后端。后端基于 SQLite 查询可见且未售出的商品，按条件过滤后返回分页结果。

首页主推专栏继续使用已有 `showcase_sections` 和 `showcase_section_items`，但前端展示样式升级。主推专栏仍然由后台手动维护，保证你想推什么就推什么。

## 接口设计

### 商品分页接口

修改现有公共商品接口：

```text
GET /api/public/products
```

支持查询参数：

```text
query       搜索关键词，匹配型号、品牌、展示文案、短卖点、推荐标签
brand       品牌
priceMin    最低价格
priceMax    最高价格
tags        逗号分隔的标签，例如 冷白皮,新手推荐
limit       每页数量，默认 80，最大 120
offset      偏移量，默认 0
```

返回结构：

```json
{
  "products": [],
  "total": 16026,
  "limit": 80,
  "offset": 0,
  "hasMore": true
}
```

### 筛选元数据接口

新增公共筛选接口：

```text
GET /api/public/filters
```

返回：

```json
{
  "brands": ["佳能", "索尼", "三星"],
  "tags": ["新手推荐", "礼盒装", "长焦", "自拍", "小巧", "冷白皮", "氛围感"],
  "pricePresets": [
    {"label": "500以内", "priceMin": 0, "priceMax": 500},
    {"label": "800以内", "priceMin": 0, "priceMax": 800},
    {"label": "千元热门", "priceMin": 800, "priceMax": 1200},
    {"label": "300-500 推荐", "priceMin": 300, "priceMax": 500}
  ]
}
```

品牌列表由数据库商品自动生成。标签列表本阶段使用固定销售标签，后续可改成后台可配置。

## 数据库与仓库设计

新增仓库方法：

```python
search_products(
    query: str = "",
    brand: str = "",
    price_min: int | None = None,
    price_max: int | None = None,
    tags: list[str] = [],
    limit: int = 80,
    offset: int = 0,
) -> ProductSearchResult
```

查询规则：

1. 只返回 `visible = 1` 且 `sold = 0` 的商品。
2. 品牌精确匹配。
3. 价格按 `display_price` 范围过滤。
4. 搜索词匹配 `model`、`brand`、`display_copy`、`raw_copy`、`short_selling_point`、`recommend_tags`。
5. 标签筛选匹配 `recommend_tags` 和自动规则标签。
6. 排序沿用当前库存排序：优先最近发布时间，再按创建时间。

建议索引：

```sql
create index if not exists idx_showcase_products_public
on showcase_products(visible, sold, published_at);

create index if not exists idx_showcase_products_brand_price
on showcase_products(brand, display_price);
```

## 标签规则

商品标签来源分两层：

1. 手动标签：后台商品管理里的“推荐标签”字段。
2. 自动标签：根据文案关键词实时识别。

自动规则：

| 标签 | 匹配关键词 |
|---|---|
| 新手推荐 | 新手、操作简单、闭眼入、好上手 |
| 礼盒装 | 礼盒、精品礼盒、送礼 |
| 长焦 | 长焦、10倍、12倍、20倍、25倍、30倍、演唱会 |
| 自拍 | 自拍、翻转屏 |
| 小巧 | 小巧、便携、超薄、口袋 |
| 冷白皮 | 冷白皮、冷白 |
| 氛围感 | 氛围感、胶片感、复古 |

如果商品同时有手动标签和自动标签，前端展示去重后的合集。手动标签优先保留。

## 客户页交互设计

### 商品列表

页面首次加载：

1. 加载访问状态。
2. 需要口令则显示口令页。
3. 口令通过后加载筛选元数据。
4. 请求第一页商品：`limit=80&offset=0`。
5. 显示 `80 / total 台`。

点击“显示更多”：

1. offset 增加当前已加载数量。
2. 请求下一页。
3. 追加到当前商品列表。
4. 没有更多时隐藏按钮。

搜索和筛选变化：

1. 清空当前商品列表。
2. offset 回到 0。
3. 请求新的第一页。
4. 更新总数和商品卡片。

### 细筛选 UI

筛选区保留现有搜索、品牌、价格。新增一行快捷筛选按钮：

```text
新手推荐  礼盒装  长焦  自拍  小巧  冷白皮  氛围感
500以内  800以内  千元热门  300-500 推荐
```

标签按钮可多选。价格快捷按钮为单选，选择后同步到价格区间。

### 复制咨询文案

商品卡片和详情页增加按钮：

```text
复制咨询文案（点一下复制这台完整文案，回微信发给我）
```

复制内容：

```text
我想咨询这台 CCD：

型号：{model}
品牌：{brand}
价格：{displayPrice} 元

完整文案：
{displayCopy}

商品链接：
{currentProductUrl}
```

按钮行为：

1. 点击后阻止商品卡片跳转。
2. 优先使用 `navigator.clipboard.writeText`。
3. 成功后按钮短暂显示“已复制”。
4. 如果浏览器不支持自动复制，则弹出可手动复制的文本框。

### 返回列表保留位置

进入详情页前，首页保存：

```json
{
  "query": "",
  "brand": "",
  "priceMin": null,
  "priceMax": null,
  "tags": [],
  "loadedCount": 160,
  "scrollY": 2400,
  "selectedProductId": "source-2026-08-10-canon-ixus80"
}
```

保存位置使用 `sessionStorage`，只影响当前浏览器会话。

从详情页返回：

1. 优先使用浏览器返回。
2. 首页检测到保存状态后，恢复筛选条件。
3. 自动加载到上次数量。
4. 回到上次滚动位置。

## 首页主推专区升级

继续沿用当前后台专栏管理，但前端样式升级：

1. 第一个专栏作为大橱窗展示，适合“今日主推”。
2. 后续专栏作为横向橱窗或紧凑网格展示。
3. 推荐使用以下默认专栏名称：
   - 今日主推
   - 预算 300-500 推荐
   - 新手闭眼入
   - 礼盒装专区
   - 最近上新

专栏商品仍然手动维护。这样你可以控制首页最显眼位置展示哪些机器，不受 Excel 时间字段影响。

## 测试计划

### 后端测试

1. 商品分页只返回 limit 数量。
2. total 返回完整匹配数量。
3. 搜索关键词能匹配型号、品牌、文案、短卖点、标签。
4. 品牌筛选只返回对应品牌。
5. 价格筛选只返回价格范围内商品。
6. 标签筛选能匹配手动标签和自动标签。
7. 隐藏商品和已售商品不会出现在公共分页接口。
8. 筛选元数据接口返回品牌、标签和价格快捷项。

### 前端验证

1. 首次进入客户页只加载第一页。
2. 点击显示更多能追加商品。
3. 搜索和筛选后重新加载第一页。
4. 复制咨询文案在卡片和详情页都可用。
5. 从详情页返回后恢复筛选条件和滚动位置。
6. 手机宽度下筛选按钮、卡片按钮、主推专区不重叠。

### 浏览器验证

使用 Playwright 验证：

1. 未输入口令时不请求商品列表。
2. 输入口令后能加载第一页商品。
3. 搜索“三星”后接口返回变小。
4. 点击显示更多后数量增加。
5. 点击复制咨询文案后按钮显示“已复制”。
6. 详情页返回后列表位置恢复。

## 风险与处理

1. SQLite `LIKE` 搜索在 16026 台规模下可接受；如果未来库存大幅增长，再升级全文搜索。
2. 自动标签依赖文案关键词，可能有漏判；后台手动标签用于修正重点商品。
3. 复制功能在部分手机浏览器可能受限制；提供手动复制兜底。
4. 返回滚动位置需要等商品重新加载完成后再恢复，否则会跳不到原位置；前端需要在加载完成后延迟恢复一次。
